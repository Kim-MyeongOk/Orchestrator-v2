# Skill: Pull Request (PR) Message Generator

## Description
개발된 기능, 리팩토링, 버그 수정 내역을 전달받아 직관적이고 표준화된 한국어 PR 메시지를 작성합니다. 백엔드/프론트엔드 변경점, 검증 결과, 기술 세부사항, 주의사항 및 PR 체크리스트를 체계적으로 정리합니다.

---

## Output Format & Rules

PR 메시지는 작성 시 반드시 아래 구조와 마크다운 형식을 엄격히 준수합니다.

### 1. PR 제목 형식
`[Type/Type] 요약 제목`
- **Type 종류**: Feat, Fix, Refactor, Chore, Docs, Perf, Test
- 복합 작업일 경우 `[Feat/Refactor]` 형태로 결합 가능
- 예시: `[Feat] 대화 압축 파이프라인 + 백엔드 구조 (src → backend)`

### 2. PR 본문 구조 (템플릿)

```markdown
[Type] 요약 제목

## 요약 (또는 개요)

작업의 핵심 목적과 결과를 2~3줄로 명확하게 요약합니다.
(무엇을 구현했는지, 어떤 문제를 해결했는지, 기술 스택 및 라이브러리 사용 여부 강조)

---

## 변경 사항 (또는 주요 변경 사항)

### 1. [기능/영역 이름 1] (필요 시 버전/이슈 번호)
- **주요 모듈/컴포넌트/테이블**: 변경점 요약
  - 세부 구현 항목 1
  - 세부 구현 항목 2 (기술적 효과나 기대 결과 명시)

### 2. [기능/영역 이름 2]
- **주요 모듈/컴포넌트/테이블**: 변경점 요약
  - 세부 구현 항목 1

---

## 검증 (또는 검증 및 테스트 결과)

- [x] **[테스트 항목 1]**: 검증 방식 및 결과 (예: 임계치 판정, 전수 검증)
- [x] **[테스트 항목 2]**: Pytest/Jest 테스트 케이스 통과 여부 (예: 총 69개 성공)
- [x] **[테스트 항목 3]**: 앱 상태 및 라우터/인포트 정상 동작 확인

---

## 기술 세부사항 (또는 기술 세부)

- **핵심 알고리즘/임계치**: 동작을 결정짓는 주요 수치나 파라미터 (예: 메시지 14개 또는 토큰 3000개 초과 시)
- **예외/안전성 처리**: 실패 시 대응 로직 (예: 요약 실패 시 기존 요약 유지 및 정상 진행)
- **최적화 기법**: 성능을 극대화한 방식 (예: 180자 분할 재생으로 브라우저 15초 제한 우회)

---

## 주의사항

- **실행/환경 주의**: 실행 명령 변경점, 필수 설정값 (예: 백엔드 실행 명령 `python backend/server.py`)
- **시스템/OS 의존성**: Windows/Mac 한계나 시스템 기본 설정 필요 유무
- **미지원/제한 사항**: 특정 조건에서의 동작 제약 사항

---

## PR 체크리스트

- [x] 빌드 통과 여부
- [x] 외부 라이브러리/의존성 추가 여부 명시
- [x] 프로젝트 코드 컨벤션 및 기존 패턴 준수
- [x] 에러 처리 및 폴백(Fallback) 동작 확인
