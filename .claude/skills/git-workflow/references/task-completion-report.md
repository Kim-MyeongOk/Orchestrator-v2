# Skill: Task Completion Reporter (작업 완료 및 Git/PR 가이드 리포터)

## Description
클로드(AI)가 생성한 코드에 대해 **스스로 테스트를 실행하여 통과(Pass)를 확인한 시점**에, 작업 내역을 종합하여 **1) 커밋 메시지 & 브랜치명 추천**, **2) 현재 시점의 PR 올려서 머지할지 여부 판단**, **3) PR 제목 및 본문 작성**을 한 번에 리포트 형태로 제출하는 스킬입니다.

---

## Trigger Condition (발동 조건)
- 클로드가 코드를 작성/수정한 후, **테스트(Pytest, Jest, 빌드 검증 등)를 직접 수행하여 전수 통과(Pass)한 것을 확정한 직후** 답변 하단에 자동으로 발동합니다.
- (테스트가 실패하거나 오류가 있는 경우에는 발동하지 않으며, 에러 수정 작업을 먼저 진행합니다.)

---

## Output Structure (출력 형식)

클로드가 테스트 성공 사실을 안내한 뒤, 답변의 맨 마지막에 아래 **3단계 항목**을 반드시 포함하여 작성합니다.

---

### 1. 📌 추천 브랜치명 & 커밋 메시지

- **추천 브랜치명**: `{type}/{kebab-case-keyword}`
- **추천 커밋 메시지 (3가지 스타일)**:
  - **[명확/정석]**: `feat: 작업 내용 직관적 요약 (주요 변경점 기술)`
  - **[기술/아키텍처]**: `feat: 적용된 핵심 기술, DB, 미들웨어 관점 강조`
  - **[간결/요약]**: `feat: 핵심 작업 내용 1줄 축약`

---

### 2. 🚦 지금 PR을 올리고 머지해야 할까? (PR 판단 가이드)

현재 작업 단계에서 **"지금 당장 PR을 올려서 머지(Merge)해야 하는지"** 아니면 **"다음 작업까지 얹어서 더 진행해도 되는지"** 명확한 판단과 이유를 제시합니다.

- **판단 결과**: `[즉시 PR 및 머지 추천]` 또는 `[다음 작업 연계 진행 추천]`
- **이유**:
  - 메이저 구조 변경(예: 마이그레이션, DB 스키마 수정, 백엔드 폴더 이동)은 **즉시 머지**하여 안전한 체크포인트를 확보하도록 안내.
  - 소규모의 연관성 높고 연속적인 서브 기능 작업은 **연속 진행**을 권장.

---

### 3. 📝 PR 작성 (제목 및 본문)

(1단계/2단계에서 PR 올리는 것을 추천했거나, 사용자가 요청한 경우 아래 포맷으로 작성)

```markdown
[Type] 요약 제목

## 요약

작업의 핵심 목적과 결과를 2~3줄로 명확하게 요약합니다.
(구현한 내용, 해결한 문제, 사용된 주요 라이브러리 및 스택 강조)

---

## 변경 사항

### 1. [기능/영역 이름 1]
- **주요 모듈/컴포넌트/테이블**: 변경점 요약
  - 세부 구현 항목 1
  - 세부 구현 항목 2

### 2. [기능/영역 이름 2]
- **주요 모듈/컴포넌트/테이블**: 변경점 요약
  - 세부 구현 항목 1

---

## 검증 및 테스트 결과

- [x] **[테스트 1]**: 검증 방식 및 결과 (예: 전수 검증 통과)
- [x] **[테스트 2]**: Pytest/Jest 등 테스트 케이스 통과 여부 (예: N개 성공)
- [x] **[테스트 3]**: 앱 상태 및 라우트/임포트 정상 동작 확인

---

## 기술 세부사항

- **핵심 알고리즘/임계치**: 동작을 결정짓는 주요 수치나 파라미터
- **예외/안전성 처리**: 실패 시 대응 로직 및 폴백(Fallback)
- **최적화 기법**: 성능 최적화 및 낭비 방지 로직

---

## 주의사항

- **실행/환경 주의**: 실행 명령 변경점, 필수 설정값
- **시스템/OS 의존성**: 시스템 설정 필요 유무
- **미지원/제한 사항**: 특정 조건에서의 동작 제약 사항

---

## PR 체크리스트

- [x] 빌드 통과 여부
- [x] 외부 라이브러리/의존성 추가 여부 명시
- [x] 프로젝트 코드 컨벤션 및 기존 패턴 준수
- [x] 에러 처리 및 폴백(Fallback) 동작 확인
