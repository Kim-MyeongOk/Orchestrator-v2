# 문서 동기화

코드를 고치면 문서도 같이 고쳐야 한다. 사람은 잊으므로 여기에 규칙을 둔다.
**코드 수정을 제시하는 답변 안에서 문서 수정도 함께 수행한다.** 별도 요청을 기다리지 않는다.

## 대상 세 가지

| 문서 | 위치 | 무엇을 담나 |
|---|---|---|
| 코드 인덱스 | `.claude/index/**/*.md` | 소스 한 파일당 문서 한 개. 역할과 하위 함수 요약 |
| 시스템 설계서 | `.claude/SYSTEM_DESIGN.md` | 요청 흐름 · API 스키마 · 그래프 구조 · DB/Redis 구조 |
| 사용자 설명서 | `.claude/USER_GUIDE.md` | end-user 관점의 사용법과 옵션 |

## 무엇을 고쳤을 때 무엇을 갱신하나

| 변경한 것 | 인덱스 | 설계서 | 사용자 설명서 |
|---|:---:|:---:|:---:|
| 클래스·컴포넌트 추가/삭제/역할 변경 | ✅ | ✅ | |
| 파일 위치 이동 | ✅ | | |
| API 엔드포인트 · 요청/응답 스키마 | ✅ | ✅ | ✅ |
| 그래프 구조 · 미들웨어 · 파이프라인 | ✅ | ✅ | |
| PostgreSQL 스키마 · Redis 키 | ✅ | ✅ | |
| 대화 압축 임계치 | | ✅ | ✅ |
| 환경변수 추가/변경 | | ✅ | |
| UI 기능 · 화면 · 버튼 동작 | ✅ | | ✅ |
| 응답 형태 (NDJSON · 생각 과정 · TTS · 에러) | | ✅ | ✅ |

## 먼저 대조기를 돌린다

문서를 고치기 전에 **소스와 인덱스가 어긋난 곳부터 확인한다.**

```bash
python .claude/skills/doc-sync/scripts/check_index.py
```

세 가지를 잡아 준다. 컨텍스트를 쓰지 않고 실행만 되므로 매번 돌려도 부담이 없다.

| 분류 | 뜻 | 할 일 |
|---|---|---|
| **누락** | 소스는 있는데 인덱스 문서가 없다 | 새로 만든다 |
| **고아** | 인덱스 문서는 있는데 소스가 없다 | 지운다 (이름 변경·이동 후 정리 누락) |
| **낡음** | 소스가 인덱스보다 나중에 수정됐다 | 내용이 맞는지 확인한다 |

누락이나 고아가 있으면 종료 코드 1 을 돌려준다. 낡음은 참고용이라 0 이다.

## 인덱스 문서 규칙

소스 경로를 `.claude/index/` 아래 **같은 트리로** 대응시킨다. 확장자는 `.md` 로 바꾼다.

```
backend/app/orchestrator/saga_coordinator.py
  → .claude/index/backend/app/orchestrator/saga_coordinator.md

frontend/src/components/Chat/ChatBox.jsx
  → .claude/index/frontend/src/components/Chat/ChatBox.md
```

대응 문서가 없으면 **그 자리에서 새로 만든다.** 현재 138개를 유지하고 있다.

인덱스를 두는 이유는 전체 코드베이스를 다시 훑지 않고도 위치와 역할을 찾기 위해서다.
그래서 요약은 짧아야 하고, 파일을 열지 않고도 무슨 일을 하는지 알 수 있어야 한다.

## 변경 내역을 알린다

문서를 고쳤으면 답변에 **어느 문서의 어느 섹션이 어떻게 바뀌었는지** 한 줄로 적는다.
그래야 사용자가 문서를 다시 열어보지 않고도 무엇이 갱신됐는지 안다.

## 상세 규칙

각 문서의 양식과 발동 조건 전문이다. 형식을 정확히 맞춰야 할 때 읽는다.
